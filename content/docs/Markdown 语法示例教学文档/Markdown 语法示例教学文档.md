# Markdown 语法示例教学文档

> 本文档旨在系统演示 Markdown 的常用语法，适用于初学者学习与模仿。所有示例均可直接复制使用。

------

## 一、标题（Headings）

### 用途说明

标题用于构建文档结构，是文章的“骨架”。通过不同级别的标题，你可以清晰地划分内容层级，帮助读者快速理解文档逻辑。

### 示例写法

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

### 效果描述

上述代码会渲染为从 H1 到 H6 的六级标题，通常用于主标题、章节、小节等结构化表达。

### 注意事项

- `#` 符号后必须加一个空格，否则不会被识别为标题。
- 推荐按顺序使用标题级别，避免跳级（如 H1 直接接 H3），以保持结构清晰。
- 统一使用 `#` 形式，不推荐使用等号线（`===` 或 `---`）方式，因其仅支持两级且兼容性较差。

## 二、段落与换行（Paragraphs & Line Breaks）

### 用途说明

段落是文本的基本单位，合理分段能提升可读性。换行则用于控制同一段内的文本断句。

### 示例写法

```markdown
这是第一段文字。它包含一些说明性的内容，适合用来展示段落的基本形态。

这是第二段文字。  
这是同一段内的强制换行。
```

### 效果描述

两个段落之间有明显的垂直间距；第二段中的“强制换行”会在新行显示，但仍在同一个段落内。

### 注意事项

- 段落之间必须**空一行**才能正确分隔。
- 若需在同一段内换行，请在行尾添加**两个及以上空格**后再回车。

## 三、强调文本（Emphasis）

### 用途说明

强调用于突出关键词或短语，增强表达效果，引导读者关注重点信息。

### 示例写法

```markdown
*斜体* 或 _斜体_
**粗体** 或 __粗体__
***粗斜体***
~~删除线~~
```

### 效果描述

分别呈现斜体、粗体、粗斜体和删除线样式，视觉上具有明显区分度。

### 注意事项

- 本文统一使用星号 `*` 表示强调，建议你在写作中也保持风格一致。
- 删除线 `~~` 是 GitHub Flavored Markdown（GFM）扩展语法，大多数现代编辑器都支持。

## 四、列表（Lists）

### 用途说明

列表用于组织条目信息，使内容更条理化、易读性强，特别适合罗列要点或步骤。

#### 无序列表

```markdown
- 项目一
- 项目二
  - 子项目（缩进两个空格）
```

#### 有序列表

```markdown
1. 第一项
2. 第二项
3. 第三项
```

#### 任务列表（GFM 扩展）

```markdown
- [x] 已完成任务
- [ ] 待办任务
```

### 效果描述

无序列表使用圆点标识，有序列表自动编号，任务列表提供可勾选的复选框，常用于待办事项管理。

### 注意事项

- 列表符号后要加一个空格。
- 嵌套子项时，建议使用两个或四个空格进行缩进，保持格式整洁。
- 任务列表是 GFM 特有功能，在 GitHub、Obsidian 等平台广泛支持。

## 五、代码（Code）

### 用途说明

代码元素专为技术文档设计，用于展示编程代码、命令行指令等内容，确保其不被当作普通文本解析。

#### 行内代码

```markdown
运行 `print("hello")` 即可输出。
```

#### 代码块

```markdown
​```python
def hello():
    print("Hello, world!")
​```
```

### 效果描述

行内代码会以等宽字体和浅色背景显示；代码块则独立成块，并可根据语言实现语法高亮。

### 注意事项

- 使用三个反引号 ``` 包裹代码块，这是最通用的方式。

- 在反引号后指定语言名称（如 `python`、`js`），可启用语法高亮功能。

- > ⚠️ 注意：某些平台（如 GitHub）不支持 HTML `<script>` 标签或 Base64 图片嵌入，出于安全考虑会被过滤。

## 六、表格（Tables）

### 用途说明

表格用于结构化展示二维数据，如参数对照、配置清单、统计结果等，信息密度高且易于比较。

### 示例写法

```markdown
| 名称 | 类型 | 默认值 |
| :--- | :---: | ---: |
| width | number | 100 |
| active | boolean | true |
```

### 效果描述

生成一个三列表格，支持左对齐、居中对齐和右对齐，布局规整，适合数据展示。

### 注意事项

- 表头与内容之间用 `| --- |` 分隔行定义。
- 对齐方式由冒号位置决定：`:---` 左对齐，`:---:` 居中，`---:` 右对齐。
- 表格前后建议各空一行，确保正确解析。

------

## 七、引用（Blockquotes）

### 用途说明

引用用于突出他人言论、文献摘录或重要提示，视觉上与其他内容区分开来。

### 示例写法

```markdown
> 这是一级引用
>> 这是二级引用
>>> 这是三级引用
```

### 效果描述

每层引用左侧带竖线标识，支持多级嵌套，形成层次分明的区块。

### 注意事项

- 每个 `>` 后需加一个空格。
- 引用中可以嵌套其他元素，如列表、代码块等，增强表现力。

------

## 八、图片与链接（Images & Links）

### 用途说明

链接和图片让文档更具交互性和表现力。链接可跳转外部资源，图片则直观传达信息。

#### 链接

```markdown
[访问 CSDN](https://www.csdn.net "点击跳转")
```

#### 图片

```markdown
![替代文本](https://img-home.csdnimg.cn/images/20201124032511.png "CSDN Logo")
```

### 效果描述

链接可点击跳转至目标网页；图片正常加载时显示图像，失败时显示“替代文本”。

### 注意事项

- 替代文本（alt text）非常重要，有助于无障碍访问和 SEO。
- 推荐使用稳定图床链接，避免因链接失效导致图片无法显示。
- 如需长期可用的图片，建议使用 GitHub + jsDelivr 或本地相对路径。

------

## 九、分隔线（Horizontal Rule）

### 用途说明

分隔线用于分隔大块内容，提升文档整体结构的清晰度，常用于章节之间或风格切换处。

### 示例写法

```markdown
---
***
___
```

### 效果描述

三种写法均生成一条水平线，视觉效果相同，用于内容分区。

### 注意事项

- 建议在分隔线上下各空一行，使结构更清晰。
- 推荐使用 `---`，因其最直观且被广泛采用。

------
